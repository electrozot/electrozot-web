✅ Works for: assign/reassign/change technician scenarios

5. ADDED TABLE FOR SKILL-BASED MATCHING:
   - tms_technician_skills (Maps which services each technician can perform)
     * ts_id INT PRIMARY KEY AUTO_INCREMENT
     * ts_technician_id INT (Foreign Key → tms_technician.t_id)
     * ts_service_id INT (Foreign Key → tms_service.s_id)
     * ts_added_at TIMESTAMP
     * UNIQUE KEY (ts_technician_id, ts_service_id)

MATCHING LOGIC:
SELECT DISTINCT t.t_id, t.t_name, t.t_experience, t.t_current_bookings, 
       t.t_booking_limit, (t.t_booking_limit - t.t_current_bookings) as available_slots
FROM tms_technician t
INNER JOIN tms_technician_skills ts ON t.t_id = ts.ts_technician_id
WHERE ts.ts_service_id = ?
AND t.t_status != 'Inactive'
AND t.t_current_bookings < t.t_booking_limit
ORDER BY t.t_current_bookings ASC, t.t_experience DESC, t.t_name ASC
